# Отчёт: статический сайт на nginx в Docker

**ФИО:** Панин Александр<br>
**Проект:** ELAYCODE — статический сайт<br>
**Среда:** Windows, Docker Desktop, nginx<br>
**Адрес локального сайта:** http://localhost:8080

## 1. Цель

Развернуть статический сайт локально в контейнере nginx и обеспечить запуск через Docker Compose.

## 2. Структура проекта

| Файл или папка | Назначение |
| --- | --- |
| [public/](./public/) | HTML, CSS, JavaScript и изображения сайта |
| [Dockerfile](./Dockerfile) | Сборка образа на основе nginx |
| [nginx.conf](./nginx.conf) | Настройка веб-сервера |
| [compose.yaml](./compose.yaml) | Сборка и запуск контейнера |
| [.dockerignore](./.dockerignore) | Исключение лишних файлов из контекста сборки |
| [screen.mp4](./screen.mp4) | Видео демонстрации |

## 3. Развёртывание

После запуска Docker Desktop в терминале из корня проекта выполняются команды:

```powershell
docker compose up --build -d
```

Команда `docker version` проверяет доступность Docker и показывает версии клиента и сервера. `docker compose version` показывает установленную версию Compose. После запуска `docker compose ps` выводит контейнеры проекта, их состояние и проброшенные порты.

В браузере открывается http://localhost:8080. Для просмотра логов использовать `docker compose logs -f`, для остановки и удаления контейнера — `docker compose down`.

Compose собирает образ из [Dockerfile](./Dockerfile), открывает порт 8080 и подключает папку [public/](./public/) в контейнер только для чтения. После изменения файла в [public/](./public/) достаточно обновить страницу. Конфигурация nginx направляет неизвестные адреса на `index.html` и отключает кэширование ответов при локальной проверке.
